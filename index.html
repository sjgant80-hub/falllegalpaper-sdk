FallLegalPaper SDK

A JavaScript library with the document engine behind FallLegalPaper: 15 templates for SRA-regulated firms (engagement letter, terms of business, costs information, CFA, DBA, advice letter, letter before action, settlement, file closure, no-win-no-fee information, vulnerable client note, simple will, LPA information, and the section 8 possession note on Form 3A, with section 21 recorded as retired), the engine that fills them into HTML, Markdown or a printable page, and 12 offline answers on SRA and court rules.

It is the FallLegalPaper page's own code, taken out so a developer, or an AI agent, can call it directly. The templates are drafting aids: a solicitor reviews every document before it goes out.

Start here

  1. Install it from GitHub (it is not on the npm registry): 
    npm install github:sjgant80-hub/falllegalpaper-sdk
  2. Import what you need and call it:
    import { buildContext, renderHtml, renderMarkdown, fieldsOf, standaloneHtml } from '@ai-native-solutions/falllegalpaper-sdk';

fieldsOf('engagement');                     // the {{fields}} the template reads
const ctx = buildContext({ client: { title: 'Ms', firstName: 'Ada', lastName: 'Lovelace' } });
const { html, missing } = renderHtml('engagement', ctx);   // HTML sections + required fields still empty
const md = renderMarkdown('s8', ctx);                       // missing fields show as «path»
const printable = standaloneHtml(html, 'Engagement letter');
  3. Or use it in a browser page with no install: 
    import * as sdk from 'https://sjgant80-hub.github.io/falllegalpaper-sdk/src/index.js';
  4. Pin a commit for production (npm install github:sjgant80-hub/falllegalpaper-sdk#<commit>) so what you tested is what runs.

How it works

  1. The engine, the 15 templates, the 12 answers and the printable page are lifted from the FallLegalPaper page byte for byte (only export added). The page itself now runs the same functions: its own document rendering and its chat matcher call them. scripts/parity.mjs fails the build if a single lifted block is missing from the published page.
  2. A template is a list of sections; each has a heading, a body with {{path}} placeholders and its required fields. Filling to HTML escapes every value and marks each empty field visibly; filling to Markdown leaves values raw and shows a missing field as «path».
  3. The page's small Markdown renderer handles bold, bullet and numbered lists (and switching between them), rules, blank lines and the signature block, and escapes everything else.
  4. An offline answer is chosen when two or more of its keywords appear in your question: the longer words of its own question (five letters or more) and its acronyms (CFA, DBA, LPA, ATE, SRA). Otherwise there is no answer, rather than a guess.
  5. Every branch of the engine is pinned by exact-output tests, and the mutation gate confirms each comparison is tested (24 of 24). The page's old engine and this one were compared on every template, empty and filled with HTML-special values, with and without overrides: 120 renders, none different.

Compliance

Drafting aids for SRA-regulated firms, not legal advice. The possession templates reflect the Renters' Rights Act 2025 (England, from 1 May 2026): section 21 is recorded as retired, and the section 8 note uses Form 3A, 3 months' arrears (13 weeks if weekly or fortnightly) and 4 weeks' notice. The pre-action answer reflects the Practice Direction (14 days in a straightforward case, up to 3 months if very complex) and the Debt Claims protocol (30 days).

The explainer

Before this repair the package exported the page's browser internals (its DOM helper, its storage, its AI chip), which could not run outside a browser, and its main file did not parse. The engine that actually matters, filling templates and rendering documents, was buried inside the app and tied to its stored state.

The repair pulled that engine out as pure functions, put the same functions back into the page (the page's own rendering now calls them), and proved nothing changed: every template rendered through the old and the new code, empty and filled with awkward values, came out identical.

It also corrected the product. Three of the twelve offline answers (the CFA cap, the DBA cap and the LPA fee) could never be reached: their questions have only one long word and the matcher needs two. Acronyms now count, every answer is reached by its own question, and no answer the old matcher gave has changed. And the pre-action answer gave the debt protocol's reply period as 14 days; the protocol gives a debtor 30 days.
